## Recipe

- Model: width 384, 12 layers, 8 heads, FF width 1536.
- PT: 1,000 unfiltered teacher games, 5 epochs, batch 160, 8 spawned workers.
- PPO: 1,000 updates × 16 environments × 256 steps = 4,096,000 steps.
- PPO: 4 epochs/update, logical batch 320, microbatch 160, LR `3e-6`.
- Ante-8 target; archive returns from Antes 4–8 with probability 0.5;
  8 snapshots per Ante/phase bucket per worker.
- Milestone budget 1.0, decaying to zero over 80% of the PPO horizon.
- Fresh 100-game evaluations every 10 updates; checkpoints every 100 updates.
- BF16 transformer compute; FP32 embeddings, heads, losses, weights, gradients,
  and Adam state. Nonfinite gradients fail the affected stage.
- PPO transfers the final PT actor and starts a new critic and optimizer.
- Seed 1701; teacher worker seed streams depend on worker scheduling.

`long/manifest.json` contains the full launch configuration. Checkpoints are in
`long/checkpoints/{supervised,ppo}` and TensorBoard events in
`long/events/{supervised,ppo}`. The launcher does not restart a failed stage or
overwrite an existing manifest. PPO starts only after PT exits successfully.

## Inspect or stop

Run these on the SSH host:

```bash
supervisorctl -c /workspace/pylatro-pt-ppo.rrD410/supervisor.conf status
tail -n 50 /workspace/pylatro-pt-ppo.rrD410/training.log
cat /workspace/pylatro-pt-ppo.rrD410/long/status.json
```

To stop this run and its workers, without touching other services:

```bash
supervisorctl -c /workspace/pylatro-pt-ppo.rrD410/supervisor.conf stop training
```

`status.json` is a stage marker, not a live heartbeat; supervisor status is
authoritative after an external stop or process kill. PT writes weights after
each epoch but does not save its optimizer for exact resume. PPO writes full
resume checkpoints including Adam and worker archives. Do not restart the
whole pipeline to resume PPO: use the existing `train.py ppo --resume` command
with the matching archive/reward/environment settings from the manifest.

The host has a 15.36-core CPU quota, roughly 85 GiB RAM limit, and a 16 GiB
overlay disk. `/workspace` is **not a mounted persistent volume**: copy useful
checkpoints off-host before recycling or destroying the instance. This launcher
does not provide automatic off-host backup.

## Automatic monitoring added during PT

PT completed at 21:03:03 UTC: epoch-5 loss 1.8226 and teacher-action accuracy
0.6445, improving from epoch-1 loss 3.2642 and accuracy 0.3867. These are
training-set imitation metrics, not held-out full-game win rates.

PPO started at 21:03:14 UTC. The first update finished at 21:05:00 and the
second at 21:06:54 (about 106 and 114 seconds). Initial planning estimate:
roughly 32–40 hours for the PPO leg including evaluation overhead, **preliminary**
until enough real updates/evaluations have completed. Both initial updates had
KL below 0.001 and no rollout stalls. No full-game evaluation had completed at
that point, so this establishes numerical health, not Ante-8 improvement.

At the user's request, a separate `monitor` program now reviews the event files
every 60 seconds. It is pinned to launcher PID 2085 and this run's private
supervisor; it neither restarts training nor controls the rental itself.
Stopping training does **not** stop instance billing.

- Latest review/phase ETA: `long/monitor_status.json`.
- Review history: `long/monitor_reviews.jsonl`; service log: `monitor.log`.
- Exact thresholds and scope: `long/monitor_policy.json`.
- Stop reason, if triggered: `long/monitor_stop_request.json`.

Stopping criteria are deliberately conservative:

- Nonfinite core losses, PPO KL, entropy, or PT gradient norms. Diagnostic NaNs
  such as explained variance on constant returns are excluded.
- Three consecutive full-run evaluations below the best win rate by at least
  `max(0.02, 0.5 * best_win_rate)`. Evaluations use the trainer's fixed fresh
  seed set; repeated polls are not counted as new evaluations.
- Mean PPO KL >=0.25 for three consecutive updates.
- Recent-100 stall fraction >=0.8 for ten consecutive updates, starting at
  update 20. Low early win rate alone is never a stopping rule.
- PT epoch loss >=1.5× its best and teacher-action accuracy down >=15 percentage
  points for two complete epochs.
- Less than 2 GiB disk reserve, or no metric/log progress for 30 minutes.

PPO consumes a stop request at a completed-update boundary, writes
`ppo_monitor_stop.pt` (including Adam and archives), mirrors it to latest, and
skips any further evaluation/update. Existing best/periodic checkpoints remain.
The monitor force-stops only this supervisor program for a hang, for PT (which
has no cooperative stop hook), or if PPO fails to honor the request within ten
minutes. A forced stop can lose work since the last saved checkpoint.

The running PT process was not restarted. The new PPO child loads the added
stop-request support when PT hands off. The original launch manifest and source
checksum above predate these monitoring-only additions; `monitor_policy.json`
records the later operational policy. Learning hyperparameters are unchanged.

These are automated metric reviews, not continuous conversational model
judgment, held-out evaluation, or proof of learning quality. Reviews stay on
the host; no automatic chat notifications are configured. The monitor exits
when training exits or the pinned PID changes. To disable the monitor alone:

```bash
supervisorctl -c /workspace/pylatro-pt-ppo.rrD410/supervisor.conf stop monitor
```
