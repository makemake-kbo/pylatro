# Matched relational readout with expanded action labels

The [pooled action-coverage experiment](consequence_action_coverage_results_20260928.md) improved consequence estimates on fixed development alternatives but failed retention. Its [residual diagnosis](consequence_action_coverage_residual_results_20260928.md) finds both preference/consequence disagreement and critical prediction errors. The next controlled question is whether the existing explicit relational readout improves this result when trained with the same expanded labels and full legal-action preference objective. The earlier relational experiment used the original proposal labels and does not resolve this comparison.

Use the immutable `RelationalConsequencePredictor`: selected/retained pooled card features and global state form a 64-dimensional proposal query, which attends to the same 23 ordered frozen Joker, hand-level and history context features with four heads. The readout has 132,035 parameters, versus pooled's 131,971, a 64-parameter difference below 0.05%. All features come from the same frozen base. Preserve card slots and positional information already encoded in context features; add no hidden simulator state, RNG or game identity as model inputs.

Reuse exactly the admitted seven-slot training cache, all 292,762 original-plus-extra action labels, original normalization, full legal support, teacher target, state order and three unit loss coefficients from the completed pooled action-coverage fit. Retain CPU FP32, one thread, seed 0, AdamW learning rate .001, betas .9/.999, epsilon 1e−8, zero weight decay, gradient clipping at 1, batch 128, 20 epochs, 7,380 updates and 942,980 state presentations. This yields 5,855,240 consequence-label presentations and the same 244,984,880 legal-action presentations. Initialize the relational architecture from its original seed-0 initialization, not its previously trained weights; equal random seed does not imply equal parameters across architectures.

Before fitting, run a technical preflight at the unchanged initial model: the first three fixed training batches, backward only, zeroing gradients between batches and taking no optimizer steps. Save the first batch's complete predictions, output gradients, parameter gradients and targets. Audit its three losses/output gradients with the existing independent float64 reference, check finite parameter gradients and unchanged initial tensors, and compare valid original-proposal predictions against the saved original relational epoch-0 predictions with the established 1e−5 relative/absolute tolerance. No pooled-prediction equality is expected across architectures. Reuse the four passed relational masking/capacity/grouping tests and unchanged loss tests.

A separate saved-artifact audit verifies the preflight, exact cache/support/recipe pins and architecture-specific initial weights. Measure first-three-batch runtime, including input assembly, and project total training time by padded action cells. Before freezing the scientific fit, set its deadline to the larger of 3,600 seconds and three times that projection, rounded up, with a maximum of 21,600 seconds. If that bound would be insufficient, investigate runtime before fitting; do not silently shorten the matched exposure. Preflight and audit each have 900 seconds plus 30 seconds supervision grace.

Run exactly one exploratory relational fit, saving epochs 0/5/10/20, with the fixed epoch-20 endpoint. A saved-artifact audit checks all exposures, first-update loss/gradient/clipping/Adam arithmetic, architecture-specific initialization and all checkpoints. No automatic scientific retry, second seed or confirmation replica. Serialize native jobs and observe actual phase and owner exits before admission.

Compare against the completed pooled action-coverage endpoint on the original training/development proposal curves, all legal development actions and every selected development outcome. Use the same base-nonplay preservation, lowest-ID preference argmax ties, original-RNG targets, state weighting and 10,000 whole-game bootstrap draws with seed 1729. Hold the pooled control's 6,008 selected actions fixed for an additional paired score-MSE/BCE/Brier comparison, with its 4,936 inside-proposal and 1,072 outside-proposal actions defining fixed groups. Reconcile pooled metrics against its completed residual diagnosis. Also report predictions on the relational model's own choices, separately because those groups can change.

Reuse all seven previously assessed readout policies where state/action/outcome identities match; branch only newly selected actions. Reproduce every factual observation, teacher-play state and outcome, parent state/UID isolation, and all 128 recorded game terminals. The four existing prediction gates and four base-retention gates remain necessary before policy integration. Report paired relational-minus-pooled prediction and retention differences; passing baseline gates alone does not establish an architectural advantage. Do not select another duration or adjust gates from the new development results.

This comparison changes readout architecture only. Do not combine it with independently learned features, state diversity, consequence-based selection, a confidence gate, or world models. Development results remain exploratory; the final fresh sampled-win gain, greedy retention, independent early-attribution and final independent-fit confirmation requirements remain unchanged. No long-horizon gain is assumed.
