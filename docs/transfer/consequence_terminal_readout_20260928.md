# One terminal readout on frozen action features

**Question.** Do the wider scorer's existing action features support delayed-outcome learning when given an explicit terminal target? Its current preference orders only 214/416 terminal win/loss pairs correctly, despite improved immediate prediction. The competing explanations are inadequate linear features, insufficient data and unpredictable suffix variation. This test can reject the sufficiency of this particular readout/data recipe; it cannot establish that all frozen representations or all terminal learning fail.

**Intervention.** Fit one 385-parameter logistic readout on the saved 384-dimensional `readout[1]` activations. Keep the base, relational pathway and all existing output heads frozen. Use binary terminal wins from the audited original-RNG, common-base-controller continuations. No teacher preference, immediate score or clear auxiliary loss, and no policy integration. All three branches of a game stay together. Sort the 1,000 game seeds by SHA256 of ASCII `terminal-readout-v1:{seed}`; use the first 800 for fitting and the remaining 200 for terminal-label validation. This outcome-independent split is fixed before fitting. All 1,000 games already contributed to feature training, so this is not unseen-source-game generalization or untouched confirmation.

Standardize each coordinate using only the 2,400 training activations, population standard deviation, replacing scales below 1e-8 with one. Optimize mean binary cross entropy plus `0.001 * ||w||² / 2`; leave the intercept unpenalized. This fixed modest ridge penalty bounds a first linear probe without a coefficient sweep. Initialize zero weights and the training-prevalence logit. Use deterministic full-batch Newton steps in float64, Armijo constant 1e-4, step halving up to 30 times, at most 100 updates, and stop only at maximum absolute gradient ≤1e-8. A convergence failure is a failed fit, not permission to extend the budget. The feature pathway remains the existing CPU FP32 pathway; float64 applies only to this small statistical readout and its audit. No endpoint selection or second fit.

**Comparison.** Save training and validation outputs, BCE, Brier, action-pair ordering and restricted three-action choice outcomes. Compare prediction to training prevalence and a state-only three-ante-bucket baseline (Antes 1–3, 4–6, 7+), smoothed by two observations at training prevalence. Compare action ordering to base log probabilities, the existing centered preference and 50% tie credit. Report same-clear pairs and early/later partitions. Restricted choices include teacher proposals and are diagnostic; no restricted-choice improvement counts as autonomous policy gain. Seeds/steps/labels never enter features.

**Spending rule.** Proceed to collecting genuinely held-out source-game terminal labels only if validation BCE improves over both analytic baselines, overall pair accuracy exceeds both base and 50%, early pair accuracy is at least base, same-clear pair accuracy exceeds 50%, and restricted-choice terminal wins retain base overall and early. Require training pair accuracy to improve over base as a fitting check. These are point-estimate spending criteria, with 10,000 whole-game bootstrap intervals reported; passing them does not qualify policy integration. If they fail, retain all results, do not refit or sweep, and diagnose whether the problem is fitting or label transfer before choosing another intervention.

**Prediction and retention.** If missing supervision is sufficient, terminal prediction and action ordering should improve together, including early and same-clear decisions, without losing net assessed base wins. Better aggregate BCE alone would indicate useful state-outcome prediction without useful action discrimination. Improved training ordering with weak validation would support a transfer/data problem. Poor training ordering at a converged optimum would show this regularized linear readout is insufficient. Fresh-game win-rate effects are unknown until later evaluation. Existing rejected policies remain rejected; all held-out consequence/retention requirements and the final sampled, greedy, early-attribution and independent-confirmation standard remain unchanged.

**Budget and verification.** Reuse the completed frozen feature extraction. One serialized fit/audit owner, at most 600 seconds per phase plus 30 seconds grace, expected seconds to minutes. Independently verify source splits, feature normalization, objective/gradient/Hessian calculations, logged accepted updates, final stationarity, every prediction and metric, and bootstrap intervals. This numerical audit is not an independent training replica. Admit only after the entire owner exits successfully. No new simulation or confirmation fit in this stage.
