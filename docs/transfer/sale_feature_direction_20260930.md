# A local test for independently learnable sale-family features

The converged 193-parameter family correction learned a linear readout of frozen state and replacement features. Its 64 replacement features came from a readout trained to rank the Joker to sell. The follow-through diagnostic found persistent suppression of the sale category even after competing purchases. These observations motivate testing whether the feature projections themselves have an out-of-sample learning signal for deciding when to sell.

This diagnostic defines a separate copy of the four replacement projection tensors: state weight/bias, owned-Joker weight, and offered-Joker weight (57,408 parameters). At initialization they equal the current candidate's tensors. The existing encoder, conditional ranking path, proposal probabilities, conditional sale probabilities used for pooling, 193-parameter family readout, and normalization remain fixed. Only the copied projection coordinates are differentiated. No parameter update, new checkpoint, simulator action, or model fit occurs.

For each active SHOP state, compute the existing feature function: GELU of the summed state, owned-Joker, and offered-Joker projections; pool with the existing frozen proposal and conditional choice probabilities; concatenate the frozen 128-dimensional state with the 64 pooled features; apply the existing normalization and family weights. Its initial features and family correction must reproduce the deployed candidate within the inherited 2e-5 arithmetic tolerance. This is a hypothetical independently learnable feature path, not shared-parameter differentiation through the conditional head.

Use every previously admitted active state: 57,257 original-training states plus 228,787 additional-training states from 5,000 games, and 7,512 development states from the same exposed 128-game panel. Include positive and negative sale labels with their original uniform behavior-cloning weights. The training normalizer remains 1,013,555 original decisions; the development normalizer remains 26,045. Native inference uses the frozen MPS runtime and the original contiguous batches of 32 active indices used by the admitted feature collection. Compare the native features, original macro logits/masks, identities, and labels against that collection before accumulating derivatives.

Compute the binary sale-versus-rest NLL gradient with independent float64 calculus. Because other action distributions are held fixed, its change equals the full-action NLL change. Define exactly one direction: the negative gradient over both complete training partitions. Development labels never define, scale, or select the direction. Report the derivative of development loss along that direction, with a paired game bootstrap over all 128 development games (including games with no active states), 10,000 draws and seed 1729. Reuse the complete-game row counts as denominators. Also report current-Ante<4 and later descriptive groups and sale/non-sale components, without selecting on them.

Require native initial-function preservation, frozen checkpoint hashes, and agreement of scalar projections with accumulated gradients. Check independent analytic derivatives against CPU autograd and finite differences on synthetic cases before collection, then finite-difference the fixed training direction on the first retained example of each partition. Preserve those examples for the saved-result audit. A small remaining gradient of the converged linear readout is a consistency control, not evidence that nonlinear features are optimal.

The full run has the previously admitted feature-collection allowance of 2,673 active seconds plus 30 owner seconds. It must honor explicit pause/resume. Require actual whole-owner success and independent verification of identities, gradient projections, complete-game bootstrap and counts before admitting its result. Routine live checks are approximately ten minutes apart. Any correction after execution uses a new version; preserve failed sources and outputs.

A strictly negative upper endpoint of the development derivative interval supports specifying one separate-feature fit. It does not qualify a model, identify the global bottleneck, prove finite-step transfer, or replace unchanged retention, fresh-game win-rate, early-policy attribution, and final independent-confirmation requirements. A failed direction stops that proposal. No sweep, larger-context change, width rerun, hidden-input feature, world model, or training on the sixteen follow-through cases is part of this test.
