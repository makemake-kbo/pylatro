# One matched fit with dense teacher supervision

This prospective recipe is specified while broad label collection is running, before its partial results are inspected. It tests whether dense replacement comparisons improve transferable features beyond selected-action and future-purchase supervision. It does not reopen the rejected family-feature fit or change the policy's action-scoring architecture. Training must wait for admitted complete labels, independently verified packing/normalization, and zero-step native integration checks.

Start from the same immutable base and the same seed-zero, hidden-64 coupled replacement readout as the completed [coupled experiment](replacement_relation_experiment_20260929.md). Preserve its original 1,000-game corpus, all outcomes, row stream `consequence-weighting-20260924-v1`, logical batch 320, microbatch 32, MPS FP32, evaluation mode with gradients, trainable actor/embedding/backbone, and frozen critic parameters. Preserve AdamW, LR 3e-5, betas (0.9, 0.999), epsilon 1e-8, zero weight decay, 100-update linear warmup, no clipping, and exactly 1,000 updates. Retain ordinary action NLL and the existing prospective-purchase NLL with coefficient one and denominator 320. Use one exploratory fit; no coefficient, duration, width, initialization, or eligibility sweep.

Read the existing 64-dimensional GELU activations immediately before the relation's output layer. A separate 64-to-11 linear auxiliary readout predicts three real values and eight class logits for every ordered owned-Joker/offer pair. Its 715 parameters start exactly zero without advancing the existing RNG or changing any existing tensor. Auxiliary outputs never enter the action distribution, proposal probabilities, legal masks, or inference gate. Removing their computation at inference must leave all policy outputs identical. The policy retains the original 57,473-parameter relation; the extra parameters serve only auxiliary prediction during learning and diagnosis.

For each pair in the unchanged visible readout support, the categorical target is one of: compared; affordability/reserve rejection; capacity rejection; insufficient immediate improvement; unsafe score decrease; direct-purchase path; parent preemption; or shop-search preemption. Numeric targets are:

1. `log(trial_score / baseline_score)` where native score forecasts exist.
2. `trial_value - baseline_value` on the same scored pairs.
3. Native net `gain` only where the pair reaches final comparison.

Direct-purchase iterations with no owned-Joker slot do not supply numeric targets for hypothetical replacement pairs. Early-filter locals cannot supply forecasts. Missing numeric targets have a false mask; storage placeholders are never treated as observations. The dataset's independent audit must establish the complete status map and native quantities before packing.

Fit each numeric normalizer on training labels only, weighting each labelled decision equally and averaging its available pairs within that decision. Use the corresponding population mean and standard deviation; when the standard deviation is below 1e-8, use scale one and record the constant-column flag. Use streaming moment combination including within-decision variance. All three targets must have training support. Development uses these fixed statistics. For reporting, categorical constant baselines use training decision-balanced class counts with one pseudocount per class.

For each decision, average half squared standardized error over available pairs separately for each numeric target. Average eight-class cross-entropy over all supported pairs. A task with no labels contributes zero for that decision. The dense auxiliary row loss is the arithmetic mean of those four task losses. Sum it over the original logical batch and divide by 320, adding it with coefficient one to the two existing losses. Neither pair count, microbatch size, number of annotated rows, teacher action frequency, nor outcome changes the original decision weight. Normalizer computation and missingness rules are frozen; they cannot be adjusted after seeing development outcomes.

Zero auxiliary weights initially imply no additional gradient to the shared representation on the first update. The first auxiliary update trains the new readout; later updates can change the existing pair features and encoder. Verify the first-update auxiliary gradients against independent arithmetic and verify that the existing sale-energy output-bias and prospective-purchase gradient identities still hold. Do not interpret zero initial feature gradients as a disconnected objective. A deterministic nonzero auxiliary-weight technical fixture must demonstrate gradients reaching the relation's feature projections and encoder while leaving the policy forward unchanged.
