# Fixed-state prediction after a competing purchase

The opportunity study found that all sixteen competing purchases in its fixed eight-game panel leave the original replacement executable: six original-training cases and ten exposed-development cases. This follow-up asks what the existing policy predicts next. It does not execute the new predictions or qualify the rejected endpoint for autonomous games.

Select all sixteen SHOP_BUY alternatives from the admitted opportunity records, without selecting on new teacher or model outputs. Replay the same eight factual games with exact equality of all fourteen cached observation fields. On copies of each selected original state, execute the already recorded alternative and pack-resolution actions. Refresh the native action mask before fingerprint comparisons in every phase. Require each resulting state fingerprint and UID counter to equal the admitted transition record, and require the final phase to be SHOP. Preserve factual state and RNG.

Save all fourteen model-input arrays before and after the purchase, retaining card and Joker order. Seeds, state hashes, utility values, future actions, RNG state and native hidden fields remain metadata and must not enter model inputs. Query a fresh search teacher on each changed state, restoring UID allocation and checking factual state and Python/NumPy/Torch CPU RNG preservation. Record its new action and existing comparison values using the previously verified observer; require an uninstrumented teacher query to agree. A changed teacher action is a result, not an exclusion.

After admitting the reconstructed states, freeze a prediction protocol for the existing sale-family checkpoint and original base checkpoint. Use the frozen native MPS runtime, temperature 1, mixture 0.5, eval mode and no gradients. Before any post-state interpretation, reproduce the original saved modes and NLL values in their original contiguous 32-row cache batches. Keep the inherited NLL tolerance 1e-5 and logit/arithmetic tolerance 2e-5. No CPU game adapter, new decoder, coefficient or threshold is part of this study.

Read one modal prediction per post-state for each model, without stepping the simulator with it. Save legal-action probabilities and compare the predicted action with the original sale and the freshly queried teacher. Report original-training and development separately, including whether the teacher still requests the original sale, changes the intended sale, or chooses a different action family. A repeated delay or an immediate sale prediction is evidence about one decision only; neither proves eventual execution or win value. The base is a descriptive reference, not a new training arm.

Serialize native collection, inference and verification. State collection has a 600-active-second bound plus 30 owner seconds and the existing explicit pause/resume controller. Require whole-owner success and an independent saved-input/identity audit before admitting states. Prediction must pin those admitted inputs, source/runtime, controls and checkpoints before it runs and preserve both model hashes. Keep failed attempts and use new versions for corrections. No training, autonomous game evaluation, confirmation access, changed original gate, or claim of long-horizon success.
