# Test remaining optimization in the frozen consequence readout

The [pair-axis diagnostic](shop_pair_axes_diagnostic_results_20261001.md) finds weak same-offer removal ranking even on training teacher-sale states: 58.66%, versus 90.72% for offer ranking with the owned slot fixed. Before a new architecture, test whether the relative endpoint's existing pair-feature basis supports a better continuous-gain readout under its exact current objective.

This is one diagnostic linear fit, not a policy-training or confirmation run. Freeze the admitted relative checkpoint, all 64-dimensional pair features, every existing action output, other auxiliary outputs and the gain bias. Solve only the 64 gain-output weights in CPU float64. Start with the original 1,000-game training cache and original dense standardized float32 targets/masks; do not add data or change which states contribute. The previously completed conditional-policy output solver used a different endpoint, target and objective; it does not answer this consequence-readout question.

For each state with n observed gains, center its feature rows and standardized targets. Form weighted design rows `(feature - state_mean_feature) / sqrt(n*N)` and responses `(target - state_mean_target) / sqrt(n*N)`, where N is the original 202,141-decision corpus size. Empty states contribute no rows; singleton rows are zero. This gives the original relative gain objective, apart from the fixed common factor from its four-task mean. Use exactly one unregularized minimum-norm least-squares solve with `numpy.linalg.lstsq`, fixed `rcond=1e-12`. Do not sweep rank cutoffs, regularization, feature subsets, target weights, training duration or sale-only weighting. Report rank, singular values and the normal-equation residual; if numerical checks fail, preserve the failure rather than choosing another solver based on development performance.

First extract the original pair features, without gradients or changes to model state. Preserve original consecutive native batches of 32 so archived predictions can be reproduced. Save only legal-owned/visible-offer pairs in fixed row-major order, along with offsets and the existing weights. Compression uses observational support only; the gain mask enters the supervised solve and diagnostics, never feature construction or policy inference. Verify checkpoint identity before and after, temporary-hook cleanup, packed row alignment and all archived auxiliary outputs. A small native technical preflight must pass before broad extraction. No simulator or teacher reruns are needed.

Before outcomes, test the centered design and objective against independent difference identities, an independently accumulated normal equation, common-offset invariance, empty/singleton masks, exact recoverable targets, rank deficiency and minimum-norm behavior. Pin the plan, sources, tests, admitted checkpoint, feature-extraction recipe and evaluation recipe before their respective execution. Development data must not choose coefficients, stopping or numerical settings.

After a successful training-only solve, evaluate original and solved gain forecasts on the identical recorded support. Retain the first two and stage outputs only for reconstruction; they are unchanged. Report centered raw/normalized error, aggregate ranking and regret, owned-slot agreement on both observable and recorded-gain support, and the three fixed pair-axis groups on all labelled states and teacher-sale states. Use training points and 10,000 paired resamples of all 128 complete development games, seed1729. Predicted absolute gains remain uninterpretable because a common state offset is unconstrained. Do not create a gameplay checkpoint, hot-swap gain predictions into action scores, or advance the rejected relative policy to gameplay or confirmation.

Substantial training improvement would establish remaining optimization in this fixed auxiliary readout; held-out improvement would show that some of it transfers. Little improvement would only weaken that particular explanation: it would not distinguish feature limitations from objective weighting, target noise or an insufficiently expressive linear readout. A minimum-MSE linear fit is not an upper bound on achievable choice accuracy or on the nonlinear model. No outcome here meets the original win-rate, retention, learned early-attribution or final independent-confirmation requirements.
