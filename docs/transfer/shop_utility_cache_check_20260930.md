Restore global ID allocation after each query and preserve factual state and Python/NumPy/Torch CPU RNG. Keep every meaningful card/Joker ordering unchanged. Save all 245 complete observed traces and per-query durations. Compare aggregate query time with the admitted fresh observed-query durations descriptively; this is not a controlled hardware speed benchmark. The purpose is to establish whether existing native cache reuse is an exact collection optimization on this panel. Later collection must still reproduce every cached teacher action and retain fresh-teacher trace controls on new games.

Use a serialized native process with a 600-active-second budget and 30 owner seconds of grace. First check after approximately two minutes; do not read partial outputs. Require the actual whole-owner successful exit and an independent saved-trace auditor before admission. Any failure is preserved and disqualifies this implementation from collection until separately corrected; do not weaken equality tolerances or change scientific controls.

This is a technical prerequisite, not a new fit or evidence of generalized play. A later dense-target collection needs its own frozen population, target schema and audit. The UID study has already shown that continuous teacher values can depend on omitted information; they must be treated as noisy heuristic supervision, not observable ground truth or expected win values. No corpus relabelling, teacher modification, new architecture, policy evaluation, or confirmation is authorized by passing this check alone.
